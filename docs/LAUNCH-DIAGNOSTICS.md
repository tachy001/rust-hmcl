# 启动诊断与任务日志

日志中心展示当前任务最多保留的 500 行输出，可以按关键词或日志级别筛选。
筛选不会修改后端输出。向上滚动会暂停跟随，“继续跟随”回到最新输出。
这不是完整日志历史：开始新任务会替换当前任务，启动器重启后不会恢复。

启动任务记录实际尝试的实例，即使之后切换了当前实例，恢复入口仍针对原启动目标。
只有游戏启动任务失败时才生成线索，普通下载或复制错误不会被当作游戏崩溃。
匹配包括 Java 版本／路径、堆内存耗尽、内存预留失败、主类加载失败和明确的模组依赖冲突。
每条线索展示匹配依据和排查建议；退出码不映射为确定原因，未知错误保留原文。

线索提供 Java 管理、实例设置、模组管理或文件校验入口。
校验需明确确认才开始，缺失或已删除的实例不会启动修复；不会自动停用模组或调整内存。
Java 的实例单独覆盖仍优先于全局默认，因此 Java 线索同时提供实例设置入口。

“导出任务报告”先取得对应任务的快照，再由系统保存对话框选择位置。
取消不会写文件；报告包含任务编号、状态、启动实例、错误、线索和全部保留输出，
不只包含页面筛选后的内容。任务编号已改变的请求会被拒绝。
文件写入失败会留在日志页显示错误，不显示成功消息。

## 验证范围

- 核心检查覆盖保守匹配、不同内存故障的区分、原始依据、未知错误、任务编号保护及启动前失败的实例上下文。
- `npm run test:console` 使用明确标识的合成组件样本，检查级别与搜索、日志文本转义、恢复事件、暂停／继续跟随及浅色／深色／窄窗口。
- `npm run test:ui` 通过真实 Service 的失败任务生成报告，只模拟系统保存器选择路径及取消；不会执行 Java 或游戏。
- Windows 原生脚本检查真实 IPC 报告、启动前缺少元数据的失败上下文，以及隐藏模式拒绝打开保存对话框。只有该脚本在对应发布程序上通过后，才能声称原生验证通过。

系统保存窗口的实际交互、真实游戏崩溃样本和三端真实游戏运行仍需单独验证；合成日志不能替代这些结果。
